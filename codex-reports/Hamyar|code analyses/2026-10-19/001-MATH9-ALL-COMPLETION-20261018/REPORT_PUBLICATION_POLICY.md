# ثبت بسته‌های گزارش «Hamyar|code analyses»

این قاعده برای هر بستهٔ خروجی این نقش، از جمله QA_REPORT، CODE_REQUEST، RETURN_REPORT و شواهد همراه آن، اجرا می‌شود. ثبت گزارش در GitHub به معنی merge، فعال‌سازی محتوا، همگام‌سازی bucket یا release نیست.

۱. پیش از پاسخ نهایی، وضعیت واقعی شاخهٔ `main` مخزن `samanta-nz/Books-Data` و پوشهٔ `codex-reports/Hamyar|code analyses` را با Git بررسی کن. نام پوشه را از روی پیام قدیمی یا لینک به‌تنهایی موجود فرض نکن.
۲. بسته را در `codex-reports/Hamyar|code analyses/YYYY-MM-DD/NNN-<task-id>/` بگذار؛ تاریخ UTC و شمارهٔ سه‌رقمی بعدی همان روز را از پوشه‌های موجود تعیین کن. هیچ بستهٔ قبلی را بازنویسی نکن.
۳. گزارش خوانا، packet ساختاریافته، manifest/hash، شواهد لازم و وضعیت اجرا‌نشده را در همان پوشه ثبت کن. دادهٔ حساس، credential یا مادهٔ امضا را منتقل نکن. پیوندهای داخل گزارش باید روی GitHub قابل استفاده باشند.
۴. قبل از پاسخ نهایی، commit و push مجاز را انجام بده، سپس URL و hash فایل‌های منتشرشده را از GitHub یا Gitِ مقصد بازخوانی و تطبیق کن. در خود گزارش و پاسخ نهایی، لینک همان پوشه و فایل گزارش را بیاور.
۵. اگر push یا بازخوانی ممکن نشد، وضعیت را صریحاً `BLOCKED_NO_PUBLICATION` گزارش کن و لینک منتشرشده یا رسید جعلی نساز. فایل آمادهٔ محلی جای ثبت در GitHub را نمی‌گیرد.

برای کاری که کاربر صریحاً از انتشار GitHub منع کرده است، همان منع مقدم است و وضعیت عدم انتشار در گزارش ثبت می‌شود. دستور معتبر کاربر دربارهٔ دامنه و اختیار هر کار بر این قاعده مقدم است.
